EXPERIMENT 1  –  Head-to-head fine-tuning on factual-correction data
────────────────────────────────────────
1. Models
   • Target: Llama-2-7B-chat-hf, Mistral-7B-Instruct-v0.2, Phi-2-Instruct  (FP16; AdamW; ZeRO-2 sharding disabled – 80 GB card is sufficient)
   • Baselines to reproduce:  
     – CE-only SFT   (cross-entropy on Y_good)  
     – FIGA          (Levenshtein alignment, token-level weights=1.0)  
     – SAFARI        (cosine k-NN = 1 alignment)  
     – DiscoPOP      (KL + POP-reward)  
     – DPO           (β = 0.1, top-5 log-probs)  
     – SOFT-FAR (ours)

2. Datasets
   Training (identical for all methods)  
   • SPA 17 121 ∥ ShareGPT-clean 30 004 ∥ Auto-fact-corr 10 022  → 57 147 prompt / (bad, good) triples.
   Validation  
   • 2 000 held-out triples stratified by source (≈3.5 %)
   Testing  
   • TruthfulQA MC-1 + generation (817 Q)  
   • FEVER dev (9 654 claims)  
   • 1 000 unseen ShareGPT prompts (model-only answers, GPT-4-judge)  
   • Human eval pool (600 prompts)

3. Pre-processing
   • Tokeniser: model-native (SentencePiece for Llama & Mistral, GPT-Builder for Phi-2).  
   • Truncate prompt+answer context to ≤ 768 tokens; discard pairs that exceed.  
   • Lower-case only for TF-IDF; keep original case for training.  
   • Pre-cache:  
     – e5-large-v2 embeddings (INT8, faiss-gpu)  
     – FactualityBERT logits (float16)  
     – TF-IDF weights (scikit-learn, min_df=5)

4. Data split / seeds / repetitions
   • Seed set S = {11, 17, 23}.  Three independent fine-tunings per method/model.  
   • Model selection = best validation FactScore.  Report avg±s.d. over seeds; tie-break by latest checkpoint.

5. Training hyper-params (identical budget)
   • Batch = 4×16 tokens (accumulate 8 → eff. 512 tokens)  
   • LR 2e-5 (flat 100 steps warm-up, cosine decay)  
   • Steps 85 000  (≈ 0.96 GPU-h on A100@FP16)  
   • Max grad-norm 1.0; label-smoothing 0.1 for CE variants.  
   • Sinkhorn ε=0.05, 6 iters; λ=0.7; δ=0.1.

6. Evaluation metrics
   Primary:  
   • FactScore↑, Hallucination rate↓, GPT-4 reward↑, Human win rate↑.  
   Secondary: BERTScore, NEW-GOOD recall, FEVER evidence recall, throughput (it/s).  
   Calibration: ECE on TruthfulQA.

7. Robustness & ablations
   • Add 10 % random noise to factuality logits → measure ΔFactScore.  
   • OOD prompts (see Exp-3) – reused here as robustness slice.  
   • Ablations already defined (no OT, no fact-w, λ grid).

8. Compute profiling
   • nvprof –metrics flop_count_sp, dram_read_bytes; log every 1 000 steps.  
   • wandb: tokens/s, peak_mem, wall-clock, dollar cost (0.94 $ / GPU-h @ on-prem).  
   • FLOPs per forward ≈ 2·N_layers·d_model² ≈ 38 GF; measured vs analytic.

9. Example code snippet (huggingface-accelerate)
   ```python
   model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf", torch_dtype=torch.float16)
   tokenizer = AutoTokenizer.from_pretrained(...)
   dataloader = DataLoader(train_ds, batch_size=4, collate_fn=pack)
   opt = AdamW(model.parameters(), lr=2e-5)
   for step, batch in enumerate(dataloader):
   ```

10. Expected reporting format
   • Table 1: metrics per model (mean±s.d.).  
   • Figure 1: training loss & FactScore vs steps.  
   • Figure 2: throughput & memory bar-chart.

EXPERIMENT 2 – Many-to-many & re-ordering stress-test
────────────────────────────────────────
1. Models
   • Llama-2-7B only (single GPU).  Baselines: FIGA, SAFARI, SOFT-FAR.

2. Synthetic revision dataset (4 000 pairs) – generated once with Mixtral-8×7B-Instruct using specialised prompts; each pair manually vetted (2× annotators, κ=0.83).  Categories labeled (i)-(iv).

3. Pre-processing identical to Exp-1; additionally store token-level alignment annotation for evaluation.

4. Split & seeds
   • Train 3 200 / Val 400 / Test 400 (stratified); seeds = {3,7}. Two runs per method.

5. Training
   • 10 000 steps, batch 8×32 tokens; LR 5e-5; no warm-up.  
   • Loss functions per method.

6. Logged signals
   • NEW-GOOD span recall during train (every 200 steps).  
   • Gradient L2 on revised tokens via hooks.  
   • ΔPPL_revised = PPL_bad − PPL_good.

7. Final metrics (test set)
   • NEW-GOOD recall & precision.  
   • P_good (mean prob on gold tokens), P_bad.  
   • Training stability (loss var, grad-norm).

8. Robustness
   • Shuffle word order noise ±10 % tokens; evaluate sensitivity.  
   • Label flip (swap bad/good) on 5 % pairs – check degradation.

9. Compute profile: same procedure; expected <0.2 GPU-h.

10. Example code (gradient hook)
   ```python
   grad_stats = {}
   def hook(module, grad_in, grad_out):
       grad_stats['l2'] = grad_out[0].pow(2).mean().sqrt().item()
   model.embed_tokens.register_backward_hook(hook)
   ```

────────────────────────────────────────
1. Checkpoints
   • Best-val runs from Exp-1 (seed 17) for each method on Llama-2-7B.

   • PubMedQA (1 000 dev Q), MedMCQA (3 000 dev Q)  – accuracy.  
   • FinanceQA (8 831 Q) – macro-F1.

   • Pairwise bootstrap (10 k samples) for each metric; Holm-Bonferroni across domains.
